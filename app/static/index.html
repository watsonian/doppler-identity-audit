Review every OIDC identity across all of your workplaces in one place.

Add Workplace Tokens

Add one token per workplace, one per line. Each is named after its workplace.

Each token is named after its workplace. A label is optional: acme-prod dp.sa.xxxx or ACME_PROD=dp.sa.xxxx.

  • Use a service account token whose workplace role has View Service Account Identities. A token belongs to one workplace, so add one for each.
  • Tokens are held in this container's memory only. They're never written to disk or sent back to your browser, and they're gone when the container stops.
  • To skip this step, start the container with one DOPPLER_AUDIT_TOKEN_<NAME> environment variable per workplace, for example from a Doppler config.

    Audit Settings

    The same settings as the command-line script's flags. New thresholds apply to the current results as soon as you save them; no need to run the audit again.

    Like --stale-days. Default 90.

    Like --max-ttl, which takes seconds. Default 60 minutes.

    Like --concurrency. Applies to the next run. Default 4.

    Set When the Container Starts

    These stay fixed while the app runs, so a web page can't send your tokens to a different host.

    API host
    · DOPPLER_API_HOST, like --api-host
    Dashboard host
    · DOPPLER_DASHBOARD_HOST, like --dashboard-host
    Token variables
    · TOKEN_ENV_PREFIX, like --env-prefix

    Other Command-Line Options

    --tokens-file
    Add Tokens under Workplace Tokens, or the setup page.
    --review
    The Approve and Flag buttons on each identity, with Export Review for the record.
    --findings-only
    The With Findings tab.
    --format, --output
    Export Review (CSV) and Export JSON.
    --fail-on
    Sets the script's exit code for CI jobs, so it has no equivalent here.
